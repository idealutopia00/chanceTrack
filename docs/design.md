# Chance Track 当前设计（v0.8.0）

日期：2026-11-17。用户已更正：针对指数做决策，展示真实 K 线，结合成熟开源项目改善外观。当前文档取代 [v0.1 基金方案](archive/design-v1.md)，旧报告不改写。

## 产品行为

工作日 14:35 自动检查市场日线，本地通知；用户在观察台切换标的，查看 K 线、MACD 和金叉/死叉事件，然后记录自己的决定及执行情况。只提供观察，不下单。历史报告保留当次行情和计算结果。

## 观察对象

| 对象 | 身份 | 数据源 | 单位 |
| --- | --- | --- | --- |
| 标普500 | ^GSPC | Yahoo Finance chart | 指数点 |
| 纳斯达克100 | ^NDX | Yahoo Finance chart | 指数点 |
| 费城半导体 | ^SOX | Yahoo Finance chart | 指数点 |
| 科创创业50（双创） | 2.931643 | 东方财富日 K | 指数点 |
| 黄金 Au99.99 | 118.AU9999 | 东方财富日 K | 元/克 |

黄金是上金所现货品种，不是股票指数。默认选择与国内黄金基金底层资产较接近的 Au99.99，界面始终显示品种与单位。双创继续明确解释为科创创业50。全部对象使用真实开、高、低、收行情，没有基金代理或合成 OHLC。

Yahoo 每次请求约两年日线，东方财富最近 600 根日线。源响应需核对 symbol/code、市场或 INDEX 类型；验证日期唯一升序、价格有限为正、高低价包含开收、成交量非负、序列长度一致。异常停止该标的分析，不静默替换成基金。

## 统一交易时段与日线状态

每个观察对象指定 session_profile，来源适配器先取最近真实日K，再统一交给 market_sessions.apply_sessions。没有“黄金只看昨天”或“只给科创放开今天”的分支。交易日不是自然日，不用 date>=今天过滤。

| 配置 | 时区 | 常规交易段 | 确认时刻 |
| --- | --- | --- | --- |
| cn_equity | Asia/Shanghai | 09:30–11:30、13:00–15:00 | 15:05 |
| sge_gold | Asia/Shanghai | 日间09:00–15:30连续交易；前一交易日晚20:00–次日02:30夜盘 | 交易日15:35 |
| us_equity | America/New_York | 行情源regular段优先；常规09:30–16:00 | 实际收盘后5分钟 |

黄金普通周一交易日包含上周五20:00至上周六02:30的夜盘。夜盘K线保留行情源给出的交易日，即使该日期晚于北京时间自然日，也不是未来价格。假日前最后一个交易日晚不自动延伸到假后交易日；中国日历排除调休周末。黄金2019年起已取消原日盘午休，不能套用股票午休或15:00收盘。

共同输出phase：day（交易中）、night（夜盘）、break（休市间隔但整根日K未结束）、settling（收盘缓冲）、closed（已确认）。未开始的交易日行不纳入；包括尚未开盘的空值占位行。已开始但未到确认时刻的最后一根记为provisional_date。先过滤未开始行，再做OHLC数值校验；已开始的异常行情明确报错，不补造价格。

所有未完成日K都参与临时MACD。preview_event不写已确认事件表，正式event独立使用最近已完成日K及event_date，两个日期可以不同。收盘缓冲后重新取数才确认，不把旧报告随着墙上时钟自动改成已收盘。

美股三个指数共用纽约时区，夏令时自动换算；最新交易日如果Yahoo提供regular开收盘时间，就用该时段处理半日市。已存在的历史真实日K用于确定实际交易日，缺少的休市日不制造占位行情。没有源时段时采用常规时段，不能承诺覆盖临时停市。

中国节假日依赖chinese-calendar与周末规则，普通夜盘归属依官方常规表和节前无夜盘规则计算，不是实时同步交易所临时公告。超出日历支持年份时应更新依赖，不能猜测开市日。

“立即更新”重新向源取数；30秒后台轮询仅检测新报告，不自动请求行情。14:35日任务及失败重试节奏不变。公开行情可能延迟，采集时间不是最新成交时间。

## Module 与 Interface

| Module | Interface | 职责 |
| --- | --- | --- |
| market_sessions | apply_sessions(rows, profile, now, provider_period) → session snapshot | 交易时区、夜盘归属、休市间隔、开收盘与确认时间 |
| data | fetch(asset, as_of) → snapshot | 两个具体来源的请求、身份/OHLC 校验、完成日线过滤、来源与采集时间 |
| configuration | load/save_configuration → 配置版本 | 标的生命周期、绑定、参数校验、追加配置历史 |
| strategies | evaluate(snapshot, configs, asset, as_of) → 结果与图层 | MACD、均线、布林突破/回归与触发过滤，纯计算 |
| analysis | analyze(snapshot, as_of) → result | 用收盘计算 MACD、交叉事件及图表序列；无网络或数据库操作 |
| storage | 保存/查询报告，追加决策 | SQLite 事务、事件去重、快照及不可覆盖历史 |
| runner | run(...) → report_id | 工作日调度、补检、错误隔离、保存与通知 |
| presentation | signal_rows(report) → rows | 统一解释本次快照与上一收盘日参考，纯展示、不取数、不改指标 |
| notifications | notify(title, message) | macOS 原生通知 |
| web + static | 本地页面、表单与图表交互 | Jinja2 模板、Lightweight Charts、切换及回看 |

单应用按职责分 Module，普通函数组成 Interface，不增加单实现抽象类、插件系统或事件总线。采集及通知在 runner 调用处可替换。图表端只渲染，不自行重新计算 MACD，避免图表与信号口径分叉。

## MACD 计算

规则 macd-market-sessions-v4，basis=market_ohlc，至少 120 个样本。价格使用 close；EMA12/EMA26、DIF 的 EMA9 均为 pandas ewm(adjust=False)，以首个样本初始化。DIF=EMA12−EMA26，DEA=EMA9(DIF)，柱体=2×(DIF−DEA)。

前一根 DIF−DEA≤0 且本根>0 为金叉；前一根≥0 且本根<0 为死叉。历史标记在达到 120 样本后生成；正式事件使用最近一根已完成日线的交叉，event_date 与盘中展示的 bar_date 可能不同；盘中交叉单独为 preview_event，不把整段历史交叉补发为新事件。超过七个自然日未更新则抑制新事件。

K 线使用原始 OHLC；MACD 序列、交叉标记、最新数值均来自同一次 analysis 结果。图表默认展示最近约 126 根，可切换 63、252 根或全部，缩放不重新初始化指标。样本窗口随采集时间变化，报告保留完整输入，可复现当次结果，但不声称两年窗口等价于无限历史 EMA。

## 图表与页面

采用开源 TradingView Lightweight Charts 5.0.9（Apache-2.0），锁定版本、本地托管 JS，附 LICENSE 和 NOTICE，页面保留 TradingView 署名与链接。与 TradingView 图表软件、行情服务没有绑定关系。

- 顶部五个行情卡片切换观察对象，显示最新日线涨跌幅与行情交易日，所有未完成日K都标注未收盘。
- 单图两 Pane：真实蜡烛图与 MACD，共用时间轴、十字线、拖动和缩放。
- 红涨绿跌；DIF 金色、DEA 紫色；金叉/死叉可切换显示，未收盘标记冠以“临时”。刷新报告后记住选中的标的。
- 右侧信号状态、来源和决策表单；下方日志、快照、历史报告。
- CSS 自适应桌面及手机；无远程字体、CDN 或前端构建工具依赖。

## 页面更新

“立即更新”通过受 CSRF 保护的 POST /refresh 重新采集所有启用标的，保存一份手动报告，不发送弹窗，不受工作日、自动重试次数和截止时间约束；全部标的统一按session_profile处理最新已开始的交易日K线。更新期间显示状态并禁止重复点击。无未保存判断时跳转新报告；有草稿时只提供新报告链接，保留当前页面。

页面每 30 秒请求 /api/update-status（只查报告元数据和文件锁，不取行情）。后台生成新报告后显示提示，不主动替换当前报告。每只标的分别显示行情交易日期、最近检查时间与成功采集时间，沿用快照显示来源报告。记录草稿的表单用 Set 跟踪，离开页面前提示未保存内容；页面刷新不会自动保存草稿。

## 历史与兼容

每次报告保存观察对象副本、来源 URL、采集时间、全部 OHLC、规则参数、图表序列及分析结果、代码版本和包含静态资源/锁文件的 SHA256。新取数不覆盖旧报告，决策只追加。

旧 macd-unit-nav-v1 报告继续显示原净值及当时指标，界面明确标注历史基金口径，不绘制虚构 K 线。事件 key 使用标的、event_date（兼容旧报告 bar_date/nav_date）、规则版本和类型；不能把昨日已确认交叉记到今天的临时K线上。定时检查按日期、规则版本及尝试序号去重，升级后的指数检查不会被当天旧基金报告挡住。每次重试单独保存，parent_report_id 关联前一次报告；成功项沿用原快照，保留 checked_at、fetched_at 和 origin_report_id。旧报告和其决策不变。

## 调度、运行与异常

沿用中国工作日、14:35、当日补检和 15:00 后补发标记。每五分钟唤醒一次检查：当天定时报告全部成功后不再取数；如有 status=error，仅重取失败标的，两次尝试开始时间至少相隔五分钟，含首次最多三次，15:00 后不启动重试。15:00 后首次恢复运行仍可补检一次。warning（例如陈旧行情）不自动重试，disabled 项不重试。每次尝试保存新报告，不覆盖失败报告；通知失败仍会重试。不是交易所休市日历，不补扫全部停机历史信号。

runner 的文件锁由 CLI、定时任务、HTTP 手动更新共同使用；运行中的任务互斥，新请求明确返回忙碌，不排队、不重复采集。数据在 ~/Library/Application Support/ChanceTrack/data，运行副本在 runtime，日志在 ~/Library/Logs/ChanceTrack。源码或观察清单变更后重新安装更新；不依赖源码外接卷在线。

本地页面只监听 127.0.0.1，Host 限制、CSRF token、模板转义沿用。数据库备份用 SQLite backup。通知提交成功不等于用户已读。

## 通知统计与去重

events表示首次记录，notification_events表示首次成功提交系统通知，不能混用。静默手动报告只记录事件，不消耗首次通知；失败通知也不消耗。实际弹窗列出指数、金叉/死叉、event_date，并分别统计当前收盘交叉、首次通知、盘中待确认和采集异常。同一报告已提交后不重复发送。notifications保存正文，报告追溯可查看。“查看通知”使用原生HTML dialog：主视图由presentation.signal_rows统一生成标的、K线交易日、交叉、确认状态；检查时间和通知发送状态分开显示，不与收盘确认混用。本次观察快照每个标的一行；盘中标的的上一收盘日交叉单独放入参考区，不能与当前状态混表，缺失数据不伪造日期。手机使用带字段名的卡片布局。系统通知未来文案逐项标明信号日和确认状态，并把检查时间放在独立行。原通知正文折叠保留；已发送/失败报告优先展示保存文案，避免按现在的去重状态重新计算历史首次通知数。未发送或历史未保存正文的报告展示注明状态的预览，共用build_message和通知标题。查看只读，不发送、不写通知状态，原生弹窗支持Esc、关闭按钮及焦点约束。

SQLite兼容迁移只回填旧已提交且new_event=True的交叉，旧0计数弹窗不能算作已告知该交叉。历史报告不改写，原先没有保存的通知正文不补造。详细说明见ADR 007。

## 验收与限制

首版重点验证行情日期清楚、报告可追溯、交叉去重、决策历史和图表可读。无回测、盈利验证、止盈止损、仓位建议、基金交易或自动下单。公开非官方接口可能变动，失败会明确提示。行情实时推送、自动循环取行情、收盘后自动确认取数尚未实现；需要主动更新或等待日任务。

## 项目维护

图表、标的详情、通知模板拆到templates/partials；自有源码按语言格式化，vendor原样保留。scripts/check_project.py验证源文件、模板、清单和依赖锁，并由安装器在停止现有程序前调用；防止静态文件误写时替换正常运行版本。开发操作见development.md。旧静态预览移到archive/previews，旧数据与报告不删除。

## v0.7 标的与多策略管理

设计依据见 ADR 008。管理入口 `/manage`，初始导入 watchlist.json 到 SQLite；之后运行使用数据库配置。现有标的保留MACD绑定，均线与布林配置预置但不自动启用。新增或重新启用标的须成功采集、核对身份和样本质量；身份修改需新ID，旧ID归档。

configuration 模块提供 load_configuration/save_configuration，负责配置校验、追加版本、激活时间和并发修改保护。strategies.evaluate 是纯计算 Interface，返回各策略事件、依据与图层。MACD采用adjust=False，均线采用简单移动平均，布林采用总体标准差(ddof=0)。组合引用精确依赖版本，并保存依赖配置。

runner 保存完整 configuration 到报告；重试使用原报告配置。新策略事件采用“标的+事件日+配置及依赖版本+事件”去重。历史激活比较事件K线收盘确认时间，启用前事件仍显示但不计首次通知。配置改动对后续报告生效，不重算历史报告。管理页可查看全部配置版本JSON，报告详情保留当时策略配置。

图表主图支持每条均线/布林线独立开关，副图支持MACD开关及多MACD配置选择。点击策略结果定位对应K线。页面、系统通知都按标的与策略区分盘中状态和确认日期；原始历史通知照原文重放。

## v0.8 图表工作台

依据 ADR 009：观察列表与指标操作移到图表页，原管理页为高级入口。前端 workspace.js 管理探索草稿、模板选择、布局和局部操作；app.js 负责图表与原有检查/通知交互。workspace.py 提供按报告或独立行情快照计算的预览接口、观察清单局部命令、模板追加版本。Python/FastAPI/SQLite技术栈不变。

- 探索接口仅使用已保存快照和当时交易日，不采集行情，不插入正式事件、报告或通知。过期和样本不足仍沿用统一计算规则。
- 添加标的在本地已验证目录中按名称或代码搜索；手动添加或恢复启用通过原数据校验。仅为新标的采集独立快照，不自动生成监测绑定。
- 保存监测命令默认复制配置到当前标的，共享更新需明确选择并展示影响列表；保存后显示版本与下一次检查生效说明。
- 模板存在SQLite chart_templates，追加版本且有乐观并发检查；草稿按报告/标的存在浏览器localStorage，布局、缩放、图层开关和当前标的另存。
- 历史报告默认原始图表，探索单独展示。决策选择探索依据时由服务端按报告快照重算，写入decision_contexts，与决策同一事务保存；原报告不变。决策日志可查看独立依据JSON。
- 网络预览带序号，只应用当前标的最新请求的结果。参数输入防抖；保存失败保留草稿与决策文字。
