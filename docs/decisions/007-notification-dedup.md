# ADR 007：分离“已记录事件”和“已提交通知”

日期：2026-11-17。状态：已实施。

触发：费城半导体2026-11-16收盘死叉在14:07手动报告#8入库，send=False没有弹窗；14:35定时报告#10再次检测到同一交叉，new_event=False，旧弹窗只统计首次入库数，因此显示0。页面显示event本身，二者口径不一致。并非MACD没识别到。

选择：events保留事件首次记录语义；notification_events另记已成功提交给系统的事件key。首次通知只以该表判定，静默检查不写，通知失败不写；系统调用成功后，通知正文、提交时间及首次通知事件key在同一SQLite事务中保存。事件身份仍沿用标的+event_date+分析规则版本+交叉类型，本次不修改分析规则或清空事件表。

弹窗始终列出当前确认交叉的指数、金叉/死叉和日期，并区分当前确认交叉数与首次通知数。盘中preview_event单独列出，不写确认通知key。重复报告仍可提交日报摘要，但不会把已通知交叉算作首次；同一报告已提交后不重复发送。原生调用成功只表示提交系统，不代表用户已读；崩溃发生在提交和落库之间仍可能重发。

兼容迁移：SQLite user_version=1新增notifications.message和notification_events。仅将旧sent_at非空且原报告new_event=True的交叉回填为已通知；旧0计数弹窗、静默报告及失败通知不能回填，避免继续漏报。原始报告和旧通知时间保持不变，旧通知正文缺失不补造。

页面将“今日信号”改为“最新日线信号”，确认交叉明确展示event_date；总览区分当前交叉数和本次首次记录数。报告追溯区显示实际通知正文及提交/失败记录，便于核对弹窗。

验证：先复现静默手动检查后定时弹窗仍“全部0”的失败测试；修复后验证首次通知、跨报告去重、同报告去重、通知失败重试、正文审计、盘中/确认隔离及旧数据库迁移。
