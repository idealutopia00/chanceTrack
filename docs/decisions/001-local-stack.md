# ADR 001：本地模块化单应用

日期：2026-11-17。状态：用户已同意技术方向。

采用 Python 3.12、uv、pandas、SQLite、FastAPI/Jinja2、launchd 和 macOS 原生通知。

原因：单用户，每日数个基金；时间序列处理与可追溯数据比复杂客户端更重要。系统调度允许检查程序退出后仍按时启动。普通函数组成高内聚 Module，依赖按实际变化处注入。

不采用独立前端、桌面壳、后台任务队列和外部数据库，避免多进程协议及部署成本。页面进程与短生命周期检查进程共用 SQLite，页面停机不影响检查。

代价：电脑需联网、登录且能执行任务；休眠/关机无法保证准点。通知权限依系统设置。页面需单独启动或安装自启动，部署细节见 ADR 002。未来多用户、远程访问或复杂交互出现时再重审方案。

变更规则：改变数据口径、日历、规则参数、存储语义或模块职责时，新增 ADR 并更新 design.md；不能只改代码。
