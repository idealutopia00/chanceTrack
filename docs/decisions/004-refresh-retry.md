# ADR 004：失败项有限重试、主动更新与草稿保护

日期：2026-11-17。状态：已实现。

用户在了解更新逻辑后要求添加改进。解决三个问题：定时采集失败需自动恢复，页面缺少主动更新入口，无法清楚区分行情日期与取数时间。

## 选择

- 复用现有 launchd 五分钟检查，无额外队列或常驻任务进程。
- 自动任务初次失败后，重试 status=error 的标的及采集失败的策略基准。基准恢复时沿用成功主标的的原始行情，重算受影响策略（见 ADR 010）。两次尝试开始时间至少相隔五分钟，含首次最多三次，15:00 后停止启动重试。当天首次补检即使晚于15:00仍允许一次。warning/disabled 不重试。
- 每次尝试生成不可变报告，记录 attempt、parent_report_id。成功项深拷贝原快照，不重新取数，标记 carried_forward 和 origin_report_id，保留原检查/采集时间。存储层按日期+规则版本+尝试序号去重，交叉事件仍按原唯一键去重。
- 文件锁下移 runner，统一串行化 CLI、定时任务和网页取数；进程退出由操作系统释放锁，不需要维护任务状态表或清除残留锁文件。
- POST /refresh 受 CSRF 保护，同步返回新报告编号；FastAPI 在线程池处理请求，取数期间页面可以继续操作。手动更新全量取数，不发弹窗，不占用自动重试次数；并发请求返回409。
- GET /api/update-status 每30秒轮询，只读最新报告编号/时间和运行锁状态，不触发行情请求。后台新报告只提示，不自动重载。
- 主动更新完成、无未保存判断时进入新报告；存在草稿时提供链接，保留当前页面。按表单跟踪草稿，避免保存一个标的后误判其他标的也已保存。离开页面提示，不将草稿当作已保存决策。

## 代价和边界

自动重试只针对当天定时报告链，手动报告独立保存；手动失败需再次点击，手动成功也不重置自动链计数。警告不重试，避免因休市导致旧行情时无意义请求。后台轮询最多约30秒才显示新报告，不提供行情实时推送。

原始事件与报告不删除，旧报告上的决策不迁移到重试报告；可通过 parent_report_id/origin_report_id 回看。网络请求若很慢，下一次调度遇到运行锁会跳过，后续再检查。通知提交的审计仍按报告保存。

## 验证

Python 集成检查覆盖仅失败项重取、冷却时间、次数上限、15:00 截止、晚间首次补检、时间沿用、旧报告和决策不变、事件去重、并发锁及异常释放、网页 CSRF/409/JSON/无脚本跳转/空页面。

Node 标准库执行真实页面脚本，验证主动刷新、草稿保留、多表单保存、状态轮询与忙碌后恢复；不增加前端测试框架。

## 单次行情请求的断连处理

行情 GET 最多发起三次请求，连接失败与断连共用这个次数预算。两段带随机延迟的退避分别为 0.25–0.5 秒和 0.5–1 秒，总退避上限 1.5 秒。HTTPX 的单个网络阶段超时为 20 秒；异步超时将一次采集的请求与退避合计限制为 62 秒。三次均发生远端协议断连时，同一进程中该来源冷却 30 秒，其他来源仍可采集。任务级重试沿用原调度规则。

错误报告保留本次异常，并记录同一标的最近成功的市场行情参考价、采集时间、交易日和报告编号。旧行情仅用于展示，无法生成本次事件或通知事件。历史报告保留写入时的数据和引用。
