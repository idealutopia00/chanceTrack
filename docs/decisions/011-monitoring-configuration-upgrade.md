# 011 监测配置升级边界

状态：v0.9 升级基线，关联 #38、#34、#35。以下发布约束随实现逐阶段验收。

## 现有读写入口

| 入口 | 配置来源及写入 |
| --- | --- |
| 指标库、管理页及配置版本页 | 管理表单提交完整草稿，由 `configuration.save_configuration` 校验并追加版本；历史版本按 ID 读取。 |
| 工作台 | 目录、单标的配置、报价读取当前版本。局部修改经 `workspace.edit` 调用同一个保存函数；预览在选定行情快照上计算。 |
| CLI、LaunchAgent、网页手动检查 | 三条路径都进入 `runner.run`，以检查锁串行运行，并保存实际采用的配置。旧实现分别读取标的和规则，阶段 1 收敛为同一次读取，检查途中继续用该版本。 |
| 定时重试 | 从原检查报告恢复配置和观察列表，携带成功的快照，补完失败标的及其依赖。 |
| 模板和决策探索依据 | 模板版本保存独立的展示策略；决策依据保存所用规则与快照。两者均不写当前监测绑定。 |
| 历史报告、事件和通知 | 报告内嵌配置与结果；事件和通知用历史键索引。读取历史时保持原策略 ID 与参数。 |
| 空库默认值 | `watchlist.json` 和 `DEFAULT_STRATEGIES` 仅用于首个配置版本。发布预设在升级时单独管理。 |

## 版本及生效边界

- SQLite `user_version` 标识结构。v0.8 基线为 4，只有迁移才更改它。同一迁移事务校验所有引用、建立约束并写入结构版本；重复启动不能生成新配置版本。
- `configuration_versions.id` 是用户配置的并发前置条件和历史引用。有效操作在一个事务中追加一次快照，冲突要求重新加载。重复绑定可直接返回现有版本，保持启用时间。
- 策略 ID 标识规则，`revision` 随规则参数或组合定义改变而变。名称、分组只影响展示。组合的事件版本还含所引用规则 ID 和修订。
- 标的的 `activated` 按策略 ID 保存生效时间。新增绑定、重新启用或有效规则变更建立新的边界，在该边界及之前确认的收盘信号仅供历史参考。
- 合并先确认双方行为等价并迁移当前引用；保留项 ID 和规则修订保持原样。已绑定保留项的标的保留其绑定。迁移绑定或改写组合依赖时按迁移生效边界抑制旧信号，防止新事件身份补发历史通知。组合引用迁移可能改变其事件身份，即使最终行为相同。既有报告、事件键和已发送通知键保持原样。
- 删除仅适用于无当前引用配置。历史快照、模板版本和探索依据仍可独立读取。仅修改当前标的时复用等价规则，或新建规则再替换该标的的绑定，其他标的不受影响。

## 升级验证

阶段 0 的合成数据库覆盖等价 MACD 的 4+1 绑定、闲置副本、组合依赖、历史报告和通知、置顶备忘。用 v0.8 代码、固定时钟与合成日线生成后冻结为 `tests/fixtures/v08-monitoring.sql.gz`，可用 `gzip -dc` 检查原始 SQL。夹具恢复不调用当前版本初始化或检查逻辑，后续迁移验收从该数据库开始。

发布候选须通过全新安装、旧库升级和失败恢复。先用一致性备份在隔离副本演练，核对 ID、参数、修订、启用时间、绑定及引用集合。迁移失败时保留可恢复旧程序和备份；切换后若已有新记录，先保留新版库再确定恢复影响。迁移不触发行情检查或通知。
